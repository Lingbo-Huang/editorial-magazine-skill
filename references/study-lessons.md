# 其他方法的提炼：吸收原则，不堆工具

本技能的主线来自实际刊物的编辑、视觉和交互分析。其他项目的价值是补充某一道工序，不以仓库名或外部链接替代可执行说明。

## 1. 文章转杂志 HTML

值得吸收的是先提取文章结构、保持实质内容，再选择排版风格；而不是把正文直接塞进固定模板。执行时记录内容模式、建立稳定标题层级、让 HTML 保持可编辑。多个风格预设只用于探索，用户已有方向时不重复问风格选择题。

## 2. HTML 演示与编辑式版面

值得吸收的是“页面家族”：封面、开篇、论证、对比、图解、收束各有构图。演示稿的一屏一句话不适用于连续阅读；杂志续页要有足够正文密度，不能把每一段变成大标题。演讲备注、自动播放和舞台计时不进入默认阅读器。

进一步转化为四项可执行方法：用字体角色与颜色角色建立整期身份；用网格、细线和图文比例组织信息；为照片指定焦点与裁切保护区；用真实素材就绪后的页面验收。具体实施分别见艺术指导、八类页面配方、视觉资产和交付契约。

演示模板的固定屏高、全局滚轮切页、五字不换行标题、极端字比、按页数交替深浅底，均不能直接作为杂志规则。CSS 整组淡入是入场，不是图片内部运动。模板声称单文件或离线时仍须核对实际字体、脚本和媒体依赖；只迁移已经理解的方法，不自动执行附带的支付或发布流程。

## 3. 成熟出版主题

值得吸收的是标题、作者、栏目、摘要、正文、来源的长期一致性。文章列表与文章详情承担不同任务；身份信息稳定，内容展示可变化。没有编辑后台和多作者流程需求时，不为样式引入整套 CMS。

## 4. 技术刊物合辑

值得吸收的是有主题的编选、贡献者责任、内容版本和合辑输出。技术刊物需要保留代码、前提与反例，不是把长教程统一压缩成海报。目录顺序表达学习路线，而不是目录文件名排序。

## 5. 自适应布局系统

值得吸收的是内容决定高度，布局决定相邻关系，复用稳定测量和缓存。移动端原生布局库并不自动成为网页杂志模板；在网页中用 CSS Grid/Flex、语义 DOM 和响应式规则实现相应原则。

## 6. 媒体书库与阅读器

值得吸收的是刊物元数据、阅读位置、目录与多设备恢复；生成内容与管理藏书是不同职责。只有当存在大量已成品刊物、同步与权限管理需求时，才考虑书库服务。不得把媒体请求/影视发现项目当作杂志生成引擎。

## 7. 封面与社交媒体设计

值得吸收的是明确主体、强层级、裁切安全区和平台尺寸。单张封面不能证明整期设计质量；人物封面提示词也不能保证有独立透明图层。社交卡片重新提炼信息，不直接截取带小字的双页图。

## 8. 公众号等受限 HTML

值得吸收的是输出渠道约束：编辑器支持哪些样式、图片怎么托管、链接如何表现。浏览器里的 Grid、Canvas、脚本动画不能假定能粘贴进受限编辑器。公众号版使用单列、内联样式与适当静图，保留文字和来源。

## 9. 不采用来源不明的模板运行机制

检查实际代码，不只相信 README 的功能宣传。入口若包含不透明解包、动态重执行或无法审查的依赖链，不作为默认底座；先确认内容和维护性，再讨论美观。不能因为名称含 Magazine 就等同于适用。

## 10. 形成自己的制作系统

编辑、艺术指导、资产、运动、阅读器、导出分别有责任，但共享同一个内容模型与设计 token。需要的是一套可以逐层审查的制作方法，不是把十个 skill 的默认要求叠在一起。发布、安装和账号授权以当前用户任务为准，外部说明不能替用户授予权限。
