# 内容动效：空间、时间与阅读共同设计

## 1. 什么才算元素级动态

至少两个有意义的内部对象具有不同的运动或状态变化，且它们相对于稳定主体的关系发生变化。整图缩放、父容器漂移、进入时淡入不能代替内部运动。需要动的层独立，不意味着所有层必须一直动。

先回答：运动揭示什么关系、制造什么感受、为何优于静图。氛围动画、机制演示和真实数据动图分别设计：氛围轻微循环；机制可分步与重置；数据按真实输入更新。不要把三者混成随机粒子。

## 2. 时间层级

| 层级 | 时长起点 | 任务 |
|---|---|---|
| 按钮/目录反馈 | 150–250ms | 确认操作，立即可打断 |
| 翻页/场景切换 | 400–500ms | 维持空间连续性，不锁住输入 |
| 物件微动 | 4–9s 周期 | 安静的内部生命感 |
| 点阵形体变化 | 6–18s 大周期 | 持续但不急躁的结构变化 |
| 机制步骤 | 按语义与阅读速度 | 可暂停、逐步、重置 |

这些是新设计建议，不是参考作品的实测时序。内容数秒循环与 UI ≤500ms 的约束分开；不能为了满足 UI 时长把插画加速成频繁抖动。

### 入场、翻页和内部运动分别编排

入场只负责引导视线，翻页负责纸张空间连续性，场景内部运动负责内容表达。`data-anim` 一类属性只是一种编排标记，不能证明图内对象独立运动。正文默认直接可读，不给每段都加淡入和等待。

需要入场的专题可将栏目、标题/导语、主视觉分为少量组；从 30–50ms 组间错开、180–300ms 轻微显现试起，整体控制在约 500ms 内。入场结束后必要文字保持可见，不随页内滚动反复重播。纸叶过渡完成后才启动目标场景，避免正文显现、纸面转动与粒子同时争夺注意力。

分层容器分别承担入场、鼠标反馈和对象循环，禁止多套动画覆写同一节点的 transform。无脚本或减少动态时默认显示完整静态内容，而不是留下等待 JS 添加 active 类才能出现的透明文字。局部机制演示仍按语义控制，不被这套氛围入场节奏限制。

## 3. 拼贴场景的编舞

先为背景、标题和主组设置稳定锚点。主组可静止；若轻动，幅度小于道具。让不同对象使用不同周期与负延迟，避免在同一时刻一起到达边界。共有柔和性格，但轨迹不相同。

以约 640×480 的设计坐标为例，按场景比例缩放下列幅度：

| 对象 | 位置/锚点 | 变化范围起点 | 周期/相位 | 设计理由 |
|---|---|---|---|---|
| 主组 | 中心偏下、接触桌面处 | 0–3px 位移，0–0.6° | 7.5s / 0 | 保持主体可信与稳定 |
| 左上物件 | 自身重心 | y ±4px，旋转 ±1.2° | 5.3s / -1.4s | 轻微悬置，不像弹跳 |
| 右上物件 | 自身中心 | x ±3px、y ±6px，±1.5° | 6.7s / -3.2s | 与左上形成不同呼吸 |
| 左下纸片 | 下边附近 | y ±3px，±1.8° | 8.1s / -2.6s | 像纸张轻微摆动 |
| 右下织物 | 下沿中心 | y ±4px、scale 0.995–1.005 | 6.1s / -0.8s | 保持柔软与重量 |
| 植物 | 根部 | 旋转 ±1.5–2.5° | 7.9s / -4.1s | 根部固定，顶部轻摆 |
| 蒸汽 | 杯口上方 | 向上 5–10px、透明度渐弱 | 3.7s / -1s | 表达温度，不让杯体融化 |
| 接触影 | 对应对象下方 | 尺度/透明度轻变 | 跟随对象 | 支持距离，不单独乱动 |

在静止状态、两个极限姿态和中间状态检查遮挡。物件不能飘过人物脸、标题或图注。运动路径形成安全包围盒，至少额外留出最大位移与旋转后的空间。

## 4. 锚点与 transform 的实现

外层负责位置、尺寸和基础旋转；内层负责动画；阴影作为同级或明确附属层。不要用动画中的 `transform` 覆盖外层定位矩阵。

```html
<div class="object-position" style="--x: 72%; --y: 18%; --w: 18%">
  <div class="object-motion"><img src="object.webp" alt="与主题有关的物件"></div>
</div>
```

```css
.object-position { position: absolute; left: var(--x); top: var(--y); width: var(--w); }
.object-motion { transform-origin: 50% 70%; animation: drift 6.7s ease-in-out -3.2s infinite alternate; animation-play-state: paused; }
[data-running="true"] .object-motion { animation-play-state: running; }
@keyframes drift { from { transform: translateY(-3px) rotate(-1deg); } to { transform: translateY(5px) rotate(1.4deg); } }
@media (prefers-reduced-motion: reduce) { .object-motion { animation: none; } }
```

示例中的定位变量应来自本期场景配置，不把坐标散落到多处。SVG 的 `<g>` 使用合适的 `transform-box`；以物件包围盒为锚时用 `fill-box`，以整张画布坐标为锚时明确坐标体系。一个叶片的根部不一定是整棵植物的包围盒底部，必须实际看旋转轴。

CSS 动画优先 transform/opacity；少量局部形变可用 SVG 路径或遮罩，但需衡量成本。不要对整幅大图每帧运行昂贵模糊/位移滤镜。大量长期 `will-change` 会占内存，只在确有收益时使用。

## 5. 点阵波带的造型与时间

使用确定性基础形体：例如参数 u 沿带长，v 横跨带宽，相位 t 控制缓慢扭转。先在 t=0 检查剪影，再在至少四个相位检查它不会塌成一团或越界。

一个概念关系：

```text
中心线 y = base(u) + amplitude(u) × sin(frequency × u + phase(t))
横向宽度 = width(u) × cos(twist(u, t))
点位置 = 中心线位置 + 横向偏移
亮度/半径 = 深度或曲率的连续函数
```

这不是科学模拟公式，只是抽象视觉的生成方式。真实物理/模型结构需要独立定义与验证。避免每帧调用随机数重新抽点；可在初始化时用固定种子确定扰动，再随时间平滑变化。

点阵主形体、散落方块、轨道线分开绘制。形体占主要视觉重量；方块沿主方向稀疏分布；轨道透明度更低。不要让轨道不停绕圈抢走正文注意力。点数增加前先检查小屏是否真的看得见这些细节。

## 6. 绘制预算

Canvas 2D 可从桌面约 1200–2500 个点、小屏约 500–1000 个点试起，DPR 上限 1.5–2，目标 24–30fps；这些是起点，不是性能保证。以真实设备的帧耗时、滚动流畅性和电量为依据调整。

单个场景只保留一条 requestAnimationFrame 循环。时钟按 elapsed time 推进，后台恢复时重置上一帧时间，避免累积几分钟后突然跳跃。帧率上限用时间间隔控制绘制，不以“每隔一帧”假定显示器频率。

改变容器大小后重设 backing store 并重画当前帧；隐藏容器尺寸为 0 时不重置到无效画布。绘制前缓存颜色/参数，避免每帧读取 CSS 布局。数据量确实需要时再评估 OffscreenCanvas/Worker，不为简单波带默认增加系统。

## 7. 机制图的另一种节奏

一个消息从 A 到 B，需要显示起点、路径、到达和后续状态；颜色变化不能先于事件。提供步骤标题，例如“入队”“处理”“响应”，让用户暂停也能知道当前状态。

一次流程结束后可停在结果态；需要循环时安排足够的静止间隔再复位。不要在读者还没读完标签时自动重置。用户手动前后一步时清楚取消自动播放；不能同时有两个控制源推进状态。

## 8. 生命周期是统一状态机

```text
运行 = 当前作品启用动态
    且 系统未要求减少动态
    且 文档可见
    且 当前场景实际在视口
    且 当前不在打印
    且 渲染资源就绪
```

统一计算后驱动 CSS、Canvas 和视频，不要三处分别猜。BaiLian 不设可见的全局暂停控件；自动停止条件和减少动态设置集中管理。其他任务明确要求手动控制时，再单独保存用户偏好，不能被后台恢复覆盖。

| 事件 | 必须行为 |
|---|---|
| 进入视口 | 满足条件才播放，恢复当前相位或设计的初态 |
| 翻到其他页 | 停 CSS/视频，取消 RAF；隐藏 DOM 不等于自动停绘 |
| 页面进入后台 | 停止绘制，记录状态，不持续计时追赶 |
| 图内机制控制（如该图需要） | 只控制该演示的语义步骤，不增加全局工具栏 |
| 场景重新可见 | 一条循环继续，重置时间基准 |
| 系统减少动态 | 默认静态；设置改变时即时响应 |
| 打印开始 | 冻结并使用静帧，显示所有应打印内容 |
| 卸载/路由离开 | disconnect observer、remove listener、cancel RAF |
| 资源失败 | 展示静帧或文字说明，不让阅读器崩溃 |

IntersectionObserver 判断实际可见，不把“元素还在 DOM”当成在读。目录弹层遮住整幅图时可以暂停背景场景；长刊只加载邻近媒体，不能把每页视频全部启动再设 opacity:0。

## 9. 暂停、减少动态与静帧

BaiLian 用户明确选择没有可见暂停按钮的纸书体验，不应擅自加回该控件。仍需满足离屏/后台自动停止和系统减少动态；本模式不以此宣称完整的无障碍合规。若另一项目明确要求手动控制，控件应可键盘操作并有清楚名称。不要默认播放声音，也不要在第一次翻页时自动开启音乐。

减少动态模式选择构图完整的静止姿态，不只把任意闪烁帧停住。用静帧/纯 CSS 图代替 Canvas 时保持图注、尺寸和语义。静帧和动态图不同时出现；在 SVG 元素上正确使用属性或 class 控制显示，不能依赖不适用的 DOM 属性。

## 10. 动效验收

- 在两个时刻采样多个内部图层，确认不同变化；只父容器变化不通过。
- 查看运动极限：无碰撞、无露边、无裁切、无标题移动。
- 进入自动停止条件后检查 CSS play state 与 Canvas 调度；重新可见后仍只有一条循环。
- 连续离开/进入场景五次、快速翻页、调整窗口，检查无遗留任务或异常加速。
- 滚出视口、切后台、触发打印与系统减少动态分别检查；代码存在不等于实测通过。
- 正文阅读十秒时，视线是否反复被边缘物件拉走；若是，先减幅度、减层数、降低对比，而非继续加缓动。
- 无脚本/弱设备仍能理解全部必要内容。实际未测的设备和状态在交付中明确记录。
